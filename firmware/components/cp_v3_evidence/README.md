# Bounded v3 evidence building block

Status: host-tested C component, now linked only into the bounded Waveshare v3
trial; see its [physical acceptance](../../../docs/notes/waveshare-v3-acceptance-2026-10-30.md). It registers
no capabilities, applies no policy, opens no radio/network/storage, and uploads
nothing. It has no TF or display dependency. T-Energy can eventually supply a
Flash journal adapter; Waveshare's TF-only recorder remains independent.

The complete implemented subset is:

- Up to16address/type keys per window, all-worker population, company IDs and
  Appearance only. Limits are independently lowerable to4company values and
  2Appearance values per identifier. UUIDs, names, templates, sampling and
  classification are unsupported; adapters must not advertise them.
- Legacy reports up to31bytes and complete extended reports up to1650bytes.
  Fragments, truncation, unknown statuses/types and malformed AD are counted;
  they never contribute guessed complete evidence. Malformed reports contribute
  no prefix evidence. Examined fragment subtypes remain local diagnostics because
  the current wire shape has only `unsupported_reports` for that distinction.
- Support counts deduplicate each retained value within each report and separate
  ADV/SCAN_RSP. Repeated conflicting Appearance values remain explicit. Value
  overflow sets a partial result with unknown overflow count, rather than claiming
  an exact distinct omitted-value count without storing those values.
- Report pressure, address-overflow reports, source counters and whole-window
  canonical evidence-byte budget remain separate. Unknown ingress counters use
  null/`not_provided`. Sealing rejects a whole window before serialization if its
  output budget cannot fit. An empty window cannot produce an empty feature batch.
- One item per feature/status batch, at most4096UTF-8 bytes. Repeated calls over
  the same sealed window/context produce identical bytes and SHA-256. The parser
  matches every current committed receipt identity, sequence and custody field;
  unknown/duplicate fields, invalid dates/numbers and trailing input fail closed.
  The intentionally narrow receipt parser accepts current-server unescaped ASCII
  JSON only; escaped/non-ASCII variants are rejected pending a reviewed extension.

Candidate version labels are `cp-v3-ad/1` and `cp-v3-producer/1`. Future runtime
work must register truthful capabilities and review/allowlist these versions.
No allowlist, server or deployment configuration was changed here.

The caller supplies cryptographic entropy and SHA-256 callbacks. Tokens are fresh
per address/type per window; the mapping remains in window RAM and never enters
JSON. Duplicate generated tokens are retried at most four times, then fail the
window. The test RNG is explicitly synthetic, not a production entropy provider.
Clear a retired window with `cp_v3_window_clear` and keep it immutable after seal.

Runtime prerequisites remain: complete v3 policy/capability digest validation,
actual applied ACK and closed boundaries, trusted clocks, monotonic stream/batch
allocation, policy/source retention, durable frozen queues and stream reserves,
exact receipt-based reclamation, retry/lease handling and board resource tests.
The caller must supply measured status counters, never zero-fill unknown values.
The current server upload subset requires local raw off; this component does not
authorize concurrent TF raw plus v3 upload or change that restriction.

Run from the repository root:

```sh
UV_CACHE_DIR=/private/tmp/campuspulse-uv-cache uv run --no-project python -m unittest discover -s firmware/components/cp_v3_evidence/tests -p test_evidence.py -v
```

The harness uses generated bytes only, C address/undefined sanitizers, OpenSSL as
the host SHA-256 provider, and the actual local TypeScript envelope/evidence/status
validators. Nine feature fixtures and one status fixture also verify independent
SHA-256 and canonical evidence-byte accounting. It does not exercise server
authorization/history transactions, a device entropy source, radio, journal,
network, capture files or production.
