## BLE 与存储观察

| 原日期 / 原型范围 | 原记录中的观察 | 对新协议的意义 |
| --- | --- | --- |
| 2026-10-14 较早固件、USB 采样 | 25.02 秒内 2,361 条有效报告；已观察序号首尾间有 1 个缺口；该时段最新状态的队列/存储/持久化丢失为零 | 序号缺口和设备自报错误不是同一个量；零自报错误不能证明空口完整 |
| 2026-10-14 持久连接版本 | 恢复扫描后，242 条报告填满约 240 个空槽，发生两次 full/persistence drop；新鲜观测跨度 18.991826 秒，较早出现自动暂停 | 队满和暂停原因必须上传；不能将这一跨度宣传为连续 20 秒扫描 |
| 2026-10-14 同 boot 暂停阶段 | 192 条记录获 ACK，相应空槽增加；多个批次复用已有 HTTP 客户端/连接 | ACK、释放与资源状态分别报告；适合小批并复用 TLS |
| 2026-10-15 独立共存 boot | 7.654038 秒设备观测跨度内，新增 602 条报告与 64 个 ACK；相关失败计数保持零 | 有短时并行证据，但入流大于出流，不能推断连续全量上传可长期跟上 |

后两条的 boot 不同。旧版堆内存曾十分紧张，协议不可要求 C3 同时缓存很大的
JSON 正文、TLS 缓冲和显示缓存。具体数值只是旧布局/镜像的表现，不是 S3 的预算。

旧实现保存 80 字节报告、原载荷与 CRC，以 node/boot/seq 去重；服务端提交后 ACK，
设备只回收已确认的存储。新协议保留其语义，不沿用其二进制布局、MAC 型 node ID
或旧服务地址。原始广播数据能支持后续重新解析，不应只留下规则结论。

## 广播与车辆判断

旧版规则研究包括 Tesla 特定服务、CCC Digital Key 相关服务、Tesla company ID，
以及 NIU/NINEBOT/SEGWAY/YADEA 等名称弱提示。完整来源和限制保留在历史规则文档。
它们从未通过真实车辆逐个匹配验证，因此不能当成已验证的车辆识别器。

可保留到新设计的经验：

- 原始地址类型、RSSI、AD 字节、ADV/SCAN_RSP 和未知/畸形标记都很有价值。
- 通用 UART、电池服务、手机厂商字段或名字片段不能单独确认车辆。
- 一个车可能有多个广播，一个广播也可能来自手机、钥匙、测试设备；地址会变化。
- 名称可以伪装；company ID 标识编号归属，不证明发射端物理产品。
- 候选地址数与人工车辆数之比是 count ratio，不是 recall；计算 precision/recall
  需要独立将观测信号与实际车辆匹配。
- 主机解析/模糊测试通过，与无线完整性、车型覆盖和现场准确率分开报告。

## 校园联网观察

2026-10-15 旧记录包含 PEAP/MSCHAPv2 认证、DHCP、带证书校验的 HTTPS 上传、
ACK 与短时空间回收证据。旧试验按当时要求关闭了 RADIUS 身份校验，这只是该
试验的配置边界，不是本项目的新安全默认；上传 HTTPS 校验当时仍开启。
持续重连、长时间共存和经确认的 RADIUS 身份均未由这些短时记录证明。

因此新协议使用实际 HTTPS 结果确认可达，不能用“Wi-Fi 连上/拿到 IP”代替。
Wi-Fi 状态、上传失败、时钟状态与存储积压分别报告。旧部署成功不能证明新的
Cloudflare endpoint、手头 S3 板卡或比赛现场网络已经可用。

## 地图观察

2026-10-15/21 的历史审计保存过 40 张主图瓦片、107 条视口标注、102 条设施
记录与 8 条独立静态热门地点；后续轮廓审计得到 19 个去重要素。它们属于不同
集合，不能简单相加成唯一地点数量，也不是完整校园清单。

这些资料采用图像坐标，没有经纬度/米级配准。建筑图形是固定视角的投影轮廓，
不是已验证的地面 footprint 或 3D 建模。12 个停车 POI 不等于非机动车空位；
63 点的历史热力响应缺少时间、单位和来源说明，不能当真实实时人流。
新上传只绑定已登记的逻辑 placement，不伪造 GPS 坐标，也不从地图接口推断
设备观察到的车辆/候梯状态。第三方地图素材的展示/再分发仍需独立确认。
