## “信息不完全”目前能做到什么

当前 [v1 validator](../../worker/ingest-validation.ts) 和
[AD parser](../../worker/ble-ad.ts) 已经允许：

- 广播没有名称、UUID、厂商或服务内容：它们只是 payload 的可选 AD 元素，
  不是上传必填项。解析结果可以是空数组。
- 没有 UTC：显式传 `utc_ms:null, uncertainty_ms:null`，继续保存原始数据。
- 没有 RSSI：`rssi_dbm:null`；不是 0，也不是硬件常用的无效哨兵值 127。
- 不传身份：使用注册配置允许的 `identity:{scheme:"none"}`。
  设备不能自行把要求 MAC 的配置降级成 none。
- 类型未知：`report_type:"unknown"`。原栈类型码仍须为实际 0–255 整数。
- AD 畸形：保留字节，派生结果标记 malformed；不会因为没有解析出完整字段而丢掉证据。

但 v1 **不允许随意省略结构键**，例如去掉 `payload_length` 或 `time.utc_ms`
会导致拒绝。空字符串载荷表示实际返回零长度 AD，不应代替“未采到载荷”。
状态中的电池电压、Wi-Fi RSSI 以及窗口中的 indices 才是现有的可省略字段。

## 建议保留与放宽的边界

| 信息 | 建议 | 原因/缺失时行为 |
| --- | --- | --- |
| 节点身份、boot、batch、stream、配置/placement/dataset、seq | 保留可信归属与唯一性约束；部分上下文将来可由注册配置恢复 | 鉴权、历史归属、幂等 ACK、范围冲突和抽样解释均依赖它们；不能靠当前地点补历史 |
| 采集 mono、时钟状态；UTC 与 uncertainty | 保留相对时序；UTC/uncertainty 可未知 | 离线缓存不能用接收时间冒充采集时间；未知 UTC 不进入公开时间趋势 |
| RSSI | 可未知；通常值得保留 | 对空间/强度研究有用；null 与 0 含义不同 |
| MAC/窗口 token | 按授权策略可无 | 无身份仍可保存广播/统计报告率；不能承诺去重设备数或轨迹 |
| Name/UUID/厂商/服务/功率等解析字段 | 都不设为收录门槛；通常服务端从 raw 派生 | 本组大多数报告本来没有名称和 UUID；缺少某类不代表整条无用 |
| 完整 raw payload | 日常活动统计可关闭或采样；研究/分类时保留需要的样本 | `metrics` 配置已有关闭 raw 的路径；不能从被丢弃内容还原未知 AD 或复核分类 |
| 窗口实际时长、扫描开启时长、完整报告计数、采样/丢失/质量状态 | 要产生活动指标时必须具备，无法测量则明确未知并暂停相应指标 | 抽样报告条数不等于全部报告数；缺失指标不补零，不输出伪“无人” |
| 队列、存储、丢失、上传/ACK 失败状态 | 应周期上传；不可用须显式表示，不能默认为健康 | 当前 raw 无法解释是否存在停扫、压力或丢失 |
| 电池、Wi-Fi RSSI 等辅助遥测 | 按硬件能力选传 | 不影响已收到的 BLE 证据被保存；已有 v1 optional 字段 |

对于 **确实无法采到某些当前必填测量** 的设备，建议新增显式的协议/配置修订：

1. 列明可省略/可 null 字段与默认语义，区分 unavailable、未采集、实际为空及畸形。
   不把所有字段设成 optional，也不接受客户端自选身份策略或 dataset。
2. 一条广播的名称/UUID/厂商内容不完整时照常收录；缺少核心统计信息时保留原始证据，
   将不具备条件的指标标为不可用。`partial_window` 指时间上不满窗口，不能借此伪造缺失计数。
3. v1 保持兼容；新版本独立校验。若 wire 做精简，服务端可生成带版本的规范化视图，
   仍保留真实传输内容和缺失状态，不把默认恢复值宣传为采集值。
4. ACK 继续绑定原始冻结请求字节与原批次；重试不补字段、不更新时间、不改变分包。
   仍然整批成功或拒绝，不引入难以回收本地队列的无定义部分 ACK。
5. 固件优先补齐有效窗口及周期状态，之后再验证时钟/placement，使合格 `field`
   记录进入 [公共投影](../../worker/sensors.ts)。本次没有更改 demo 标签或公开隔离规则。

## 体积估算：先减少重复表达

对第一组批次 compact `JSON.stringify`，共 **1,167,991 B**，平均 **330.69 B/报告**。
只有 96,240 B 是二进制 AD 内容，JSON 中 hex 占 192,480 个字符。
这不是原始冻结请求或网络传输实测，不含 HTTP/TLS/压缩成本。

| 假设由新合同明确定义的省略规则 | 此数据集估算减少的字节 |
| --- | ---: |
| `payload_length`，按 hex 推导 | 70,561 |
| `format:"legacy_ad"`，由限定格式的 profile 表达 | 74,172 |
| `identity:{scheme:"none"}`，由对应授权配置表达 | 102,428 |
| UTC/uncertainty 的重复 null 键，由明确缺省语义表达 | 127,152 |
| 四项一起应用 | **374,313（32.05%）** |

精简后的该组估算为 **793,678 B，224.71 B/报告**。全部 payload、RSSI、序号、mono、
clock epoch、window_seq 及两种类型字段均保留。结果不表示已上线或证明节省同等网络流量。

结论：有依据先支持“未知/缺少辅助内容仍能收录”，并压缩重复表达。
是否进一步只传特征或过滤广播，应由活动统计/具体分类任务的需求和验证决定；
当前这批没有独立类别真值，不能据厂商字段常见就判定其他内容都无所谓。
