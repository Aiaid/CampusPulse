# 电梯候梯时间预估：后端优先方案与设备输入

日期：2026-10-24（Asia/Shanghai）。状态：**历史设计，部分已被后续实现取代。**

2026-10-28 提交审计：本文以下的“当前”“未实现”均描述 2026-10-24 的设计基线。
后续已实现 v2 地址摘要、人工候梯历史分位数参考与 BLE 可见性候选，现行能力及
边界以[自动观察说明](../specs/automatic-observations.md)为准。BLE 辅助等待预测、

本方案研究电梯厅附近的 BLE 地址及 RSSI，不依赖电梯控制系统接口。现阶段
仍展示人工实测；历史实测、蓝牙推断和当前预测必须分别存储、分别标注。

## 1. 目标、定义与职责

先限定一栋楼、一个楼层、一个电梯组，区分上下行；不推导全楼状态。
目标 `W = 实际上梯时刻 - 实际开始候梯时刻`，不含到候梯区之前的步行或乘梯时间。
“下一班电梯到达”不等于“这个人能够上梯”：满载、方向不符可能导致多轮等待。

首个产品目标是**现在刚开始候梯者的等待分布/区间**。已经等待 `a` 秒者的
剩余等待属于另一个目标，须估计 `W-a | W>a`，不能用中位数直接减去 `a`。
用户“开始等”的时刻不能由某地址首次被接收的时刻自动替代。

| 责任 | 首版位置 | 约束 |
| --- | --- | --- |
| 扫描、单调时间、队列、断网缓存、上传/ACK、损失记录 | 设备 | BLE 回调只入队；持久化、上传独立任务 |
| 按地址生成确定性的时间切片摘要 | 如采集契约采用摘要，则在设备 worker | 保留时序与质量；仅机械压缩，不判断候梯/上梯 |
| RSSI 平滑、短时片段、区域/状态/事件推断 | 后端 | 首版可回放、可换参数；多节点证据保留来源 |
| 标签对照、基线、训练、误差评估、预测有效性 | 后端/离线研究工具 | 版本化输入与模型，不阻塞接收 ACK |
| 网页和设备显示 | 拉取后端结果 | 显示来源、证据时间、有效期和不可用原因 |

Cloudflare 接收路径先完成现有持久入库/归档；推断是可重算的派生流程，
失败不能把成功接收改成失败或拖住设备回收。D1 适合保存片段索引、标签和
预测摘要，私有 R2 保留获准的有界证据/研究产物。任务触发、计算预算和模型
运行方式留待实现时验证；不默认在每次上传请求中训练或扫描全部历史数据。
后续才考虑把成熟的平滑/片段处理下放设备，必须对同一回放验证等价性。

## 2. 当前可用性与输入缺口

v1 当前只支持 `ble_windows`、`ble_reports`、`node_status`。地址时间摘要是
roadmap 中的独立版本化流提案，不能作为新增字段塞入现有白名单请求。
当前 validator 的窗口 `indices` 只支持 `report_rate`，不接受候梯指数或预测；
本设计也不把推断结果反写为设备原始测量。

- `identity.scheme=mac` 可在获准研究域内按观测地址/类型构建片段；地址不是
  永久设备或人的身份。地址轮换后默认新开片段，不凭载荷相似度强行合并。
- `window_token` 被 node/boot/window 限定，不能跨窗口或跨节点匹配；
  `none` 无法做地址关联。普通哈希或延长 token 作用域也是策略变更，不能暗改。
- 30 秒整体窗口的 unique/RSSI 汇总无法恢复某地址的进入、离开及变化顺序。
- [2026-10-24 审计](../research/ingestion-field-audit-2026-10-24.md)中的
  3,532 条固件声明组报告均为 `identity:none`、UTC/uncertainty 未知，
  按每 280 条选一条的策略抽样，且没有该组匹配的窗口/状态。
  该组登记为 demo，不能当作现场训练真值。这一批只能提供有限的广播/RSSI
  研究，不能验收候梯片段或预测；不代表此刻
  线上全部数据的状态，也不单凭版本声明证明真实空口采集。

实验输入两条路径：

1. **沿用 v1 的有界原始实验：** 获准的 `research_raw + mac` 配置，选择能够
   保留事件时序的采集密度，同时上传窗口/状态。局部全量仅限资源验证后的
   受控时段，不能因为后端优先就要求长期全量 raw。
2. **目标生产路径：** 与既定地址时间摘要主流对齐，上传细粒度切片/子桶及
   有界 raw 对照。先冻结并验证新契约、独立序号/ACK/回收、权限与资源预算。
   摘要损失了什么必须写明；只有 first/last/min/max 的长窗口摘要不满足本实验。

秒级切片可从 **1–2 秒**作为试验候选；这是待标定参数，不是精度承诺。
切片粒度、实际上报延迟、无线漏收与缓存补传是不同指标，须分别测量。

## 3. 设备需要上传的输入

下表“已有”表示 v1 契约已定义，不表示当前固件已完整采集/上传。
新设计名只描述字段语义，最终名称、单位、范围和流版本须另行冻结。

### 3.1 归属、时间与配置：沿用的必需字段

| 字段/位置 | 算法用途 | 缺失时处理 |
| --- | --- | --- |
| 信封 `protocol/batch_id/node_id/boot_id/stream` | 版本、幂等、排序和启动边界 | 拒绝非法请求；不跨 boot 拼接单调时间 |
| `placement_id/capture_config_id/dataset/firmware_version` | 还原采集地点、策略、来源与适配器差异 | 只能引用登记历史；demo/test 不混入 field |
| 每条 `seq`；raw 的 `window_seq` | 证据引用、匹配窗口与解释缺号 | 序号不是空口序号；缺号结合抽样/损失解释 |
| `time.mono_ms` | 同 boot 的顺序与相对时长 | 必需，不用接收时间代替 |
| `time.utc_ms/clock_epoch/uncertainty_ms` | 时段分组、多节点/人工标签对齐 | 未校时保留 null；限制到单节点相对回放 |
| 注册配置 `scan.stack/adapter_version/mode/interval_ms/window_ms/filter_duplicates/host_filter` | 解释广播密度、重复过滤和扫描差异 | 参数通过 config 关联，不随包重复；变更须有生效边界 |
| 注册配置 `raw_capture`、上传和保留策略 | 区分正常抽样、背压和丢失 | 不把 selected 报告数量当全部广播数量 |

多节点要根据各自 UTC 映射及不确定度对齐。允许的最大不确定度要相对于
事件时间分辨率标定；满足一般活动窗口的时钟门槛不自动满足秒级候梯事件。
UTC 未知时不得按服务器接收时间推定两节点同时消失；同节点 mono 回放仍可保留。
离线重传按采集时刻回算历史，不更新成“此刻预测”；校时跳变分段处理。

### 3.2 地址观测：首版原始输入与摘要扩展

| 必需语义 | v1 原始输入 | 新摘要契约的要求（未实现） |
| --- | --- | --- |
| 短时关联 | `identity.address/address_type`，仅授权 `mac` 模式 | 明确作用域的地址/研究关联键，允许实验所需跨窗；跨节点匹配单独授权/设计 |
| 观测时间范围 | 每条 `time.mono_ms` | 切片开始/结束与地址 `first_seen_mono_ms/last_seen_mono_ms`；注明区间边界和部分切片 |
| RSSI 时序 | 每条 `rssi_dbm`，未知为 null | 有序子桶的边界、有效样本数及统计；最少保留时间顺序，不能仅整窗均值 |
| 报告次数/类别 | `report_type/report_type_code`；计数由后端派生 | 实际进入摘要的报告数、ADV/SCAN_RSP 数量；不把两类报告当两台设备 |
| RSSI 有效性 | `rssi_dbm` 是否有值 | 各子桶 RSSI samples、min/max/mean；需要中位数/分位数时定义计算或近似方法 |
| 稀疏和间断 | 从逐条时间及质量记录推导 | 有序空桶/覆盖掩码及观察间隔信息，区分未收到报告与未扫描/缺失 |
| 来源与压缩版本 | `batch_id + seq` 及原始字节 | 摘要算法/参数版本、独立记录 ID/序号、关联窗口及可用 raw 引用；不可伪造逐包复原 |

摘要必须说明**从全部 host reports 还是从已抽样报告生成**。地址表容量、
溢出/淘汰、摘要队列丢失和切片覆盖缺失都要可观测；不能因设备表满而解释为
有人离开。相关质量可以置于独立切片/窗口记录，不要求在每个地址上重复。
切片跨配置、placement、boot 或关联键期限边界时必须拆开。

实验初期可使用现行获准的 MAC 模式，派生片段按任务限制时间与访问范围，
不做长期个人轨迹。若另设计研究 token，须明确任务/节点/时间作用域、轮换、
密钥管理及边界截断；不可宣称轮换后的身份可恢复。所有关联键和 raw 保持私有。

名称、厂商、服务 UUID、Tx Power 仅作可选研究特征，不作为收录门槛或真实
身份凭证。现行 `ble_reports` **仍要求完整 `payload_length/payload_hex` 等
结构字段**；不能因算法不依赖名称而删掉原始载荷。新摘要流可减少载荷，
但要与有界 raw 证据策略一起设计。不要默认连接 GATT、配对或查询手机。

### 3.3 扫描质量、健康和丢失：必须伴随观测

| 需要的信息 | 已有 v1 字段/来源 | 仍需补充的设计 |
| --- | --- | --- |
| 扫描覆盖背景 | `ble_windows.duration_ms/scan_enabled_ms/quality_flags` | 与地址切片对齐的覆盖信息；scan_enabled 不等于实际 RF 接收时长 |
| 总量与抽样 | `reports_seen/reports_aggregated/aggregation_drops/raw_capture.*` | 新摘要的输入/输出/跳过计数及守恒口径 |
| 地址表溢出 | 整体窗口 `unique_table_capacity/unique_table_overflow` | 摘要表自身容量/淘汰/溢出，不借用整体 unique 表口径 |
| 停扫/重启/配置切换 | `node_status.scan_state`、boot、config 及窗口质量 | 精确 mono 时间的停扫/恢复/压力/切换事件或覆盖子桶；周期快照不能定位所有间断 |
| 队列和存储 | `queue_pending/queue_capacity/storage_free_bytes/buffer_health` | 新流的独立预算、暂停与回收统计 |
| 各类故障 | `loss_totals`、`raw_capture_state` | 新流丢失/压力跳过及原因；累计计数变化本身不能定位具体故障时刻 |

电量、空闲堆、Wi-Fi 信号用于运维，不作为候梯时间的直接标签。
所有“未知”保持未知；没有报告不能补成“无人”。静止参考信标可辅助识别
共同接收异常，但它自己也可能故障，不能以单一信标推定扫描完整或上梯。

## 4. 后端算法流水线

1. **质量门控与事件时间排序。** 验证配置/地点/时间/采样，按采集时间处理
   乱序和迟到。冻结回放 cutoff、迟到处理与版本；已发布预测不可被回填数据
   伪装成当时就知道。缺失覆盖的区间标为未知，不产生确定离开事件。
2. **短时地址片段。** 按 node/boot/placement/config/观测地址类型与关联策略
   建立片段；平滑 RSSI，提取持续时间、变化趋势、间隔、波动及节点间相对值。
   间断容忍度按广播间隔、采样和现场数据标定，不固定一个通用超时。
3. **区域与状态。** 从 `经过候选 → 入区候选 → 持续停留 → 离区候选 / 疑似上梯
   / 未知` 开始。RSSI 阈值、进入/离开滞回与最短持续时间用人工标签标定，
   不把 dBm 直接换算米数；持续停留不自动等于排队。
4. **事件融合。** 多个停留片段在近似时间发生变化，可形成批量上梯候选。
   走廊节点的重现可支持走开假设；共同扫描异常要先排除。即使两节点都
   消失，也不能确认进轿厢；单一地址消失、载荷改变都不构成上梯真值。
5. **候选等待片段。** 保存开始/结束的估计范围、事件类型、证据与质量。
   最后收到包只约束“最后可见”，不等于实际上梯；超时只是确认延迟，
   不能把超时时刻直接作为上梯时刻。没有可辩护的时间界限时保持未知。
6. **参考预测。** 先训练仅用地点/楼层/方向/时段及人工完成样本的历史基线，
   再加入近期停留片段数量、进入/离开率、候选批量事件及质量特征，比较
   中位数/分位数统计或分位数回归。地址片段数、报告率均不是队列人数。

首版优先使用人工确认的完成候梯样本；未经验证的推断结果不回灌成真值。
还在等待的会话属于右删失；走开离队作为独立结果/竞争事件；开始前已在等、
地址轮换及观测中断分别标注。仅对完整可见片段评估会偏向短等待，需报告
各类丢弃/删失比例，后续再评估生存分析或区间删失模型。

派生结果至少保留 `algorithm_version`、参数/校准版本、输入配置与数据范围、
源记录引用、质量/不可用原因、计算时间；人工标签另有标签 ID、记录者来源与
纠正版本。原始数据不因重算而修改，不覆盖人工 `wait_seconds`。

## 5. 人工标签与现场信息（不属于普通 BLE 广播字段）

| 信息 | 来源与记录方式 |
| --- | --- |
| 楼栋、楼层、电梯组、节点角色/安装位置、上下行 | 服务端 placement/实验配置；不要求设备凭 RSSI 自动识别楼层或方向 |
| 实验 session、标签 ID、设备/参与者对应关系 | 受限实验登记；自愿参与者用实验代号，不把个人身份放入公开记录 |
| 到达附近、真正开始候梯、开门、实际上梯、离队 | 手机/Passport 人工事件标记，含 mono/UTC、误差及操作者来源 |
| 满载未上、方向不符、停运、多人同上、路过 | 独立事件/备注；区分未发生与未记录 |
| 更正、取消及未结束 | 不可变标签修订/取消关联；不能把取消视为零秒成功候梯 |

目前人工 API 只有完成的 `wait_seconds` 等观察字段，不支持上述完整 session
事件。这些是**待设计的标签契约**，不是设备已能上传的新增 BLE 字段。
人工开始/结束优先使用同设备单调时钟计算耗时；和其他节点对齐仍需时钟映射。

## 6. 试验、评估与公开门槛

1. 在同一电梯组放候梯区节点 A 和走廊节点 B，记录安装位置、朝向和配置。
   B 只增加离开方向的证据，不保证能覆盖整个空间或确定上梯。
2. 先用已知信标验证输入密度、时序和漏收，再用自愿参与者手机做经过、
   候梯、走开、锁屏、口袋/背包、满载未上、多轮等待及扫码/联网压力场景。
   信标与手机、受控与自然现场队列分别统计，不把信标成功率套给路人手机。
3. 为未广播或不可可靠关联的参与者记录检测覆盖率。主动参与手机的结果
   不能代表所有路人；单人多设备、地址轮换和广播间隔差异单独记录。
4. 用人工计时先验收事件识别，再评估等待预测。按完整 session/日期划分
   训练、调参和测试；同一参与者片段不随机拆入两边。预测只使用当时可用
   输入，不用事后上梯事件、后来补传或结束时间产生未来信息泄漏。
5. 实验前冻结候梯/上梯事件 precision、recall、时间误差，以及等待 MAE、
   尾部误差、预测区间覆盖率/宽度、可预测比例和刷新延迟的验收阈值。
   同时报告样本数、删失/弃用原因、手机覆盖率和不同场景结果。
   这些阈值目前未确定，不宣称达到某个秒数精度。
6. 在相同测试集比较历史基线与 BLE 模型；BLE 未带来可重复改善时保留历史
   参考或不可用状态。训练不足、扫描异常、配置/点位未校准、方向未知或
   时间不可对齐时降级；不拿模拟值填补现场数据。

公开预测契约拟包含地点/方向、目标定义、预测中位数与区间及覆盖目标、
实际标签/独立会话数量、`as_of`（证据截止时间）、`generated_at`、`valid_until`、
模型/校准版本、质量与不可用原因。数值概率的“置信度”须校准后才能展示。
有效期按证据新鲜度和验证结果设定，不能仅因刚完成计算而刷新旧证据寿命。
这不是现行 summary API 已支持的字段列表；发布前另行设计并验证输出契约。
公开结果不含 MAC、片段键或参与者轨迹；手工实测与预测各有来源和时间。

## 7. 实施切片与完成边界

- **输入契约：** 冻结细粒度地址摘要/受控 raw、短时关联、质量事件、时间对齐
  及标签接口，复用持久 ACK 约束；用合成夹具验证，再逐台实测资源和吞吐。
- **可回放推断：** 建立后端片段/事件和不可用状态，记录版本/证据；用人工
  标签量化识别误差，保留受限原始证据以复核。
- **预测对照：** 历史基线与 BLE 分位数预测做独立留出评估，记录偏差、
  删失和可预测覆盖；不以训练拟合或构建通过验收现场算法。
- **产品化：** 达到事先约定门槛后再接网页/设备显示、过期降级与运维；
  最后评估设备预处理下放，不要求 ESP32 首版完成候梯推断或运行预测模型。

优先级和未完成项以 [roadmap](ROADMAP.md) 为准。本文的文档完成不代表上述
任何运行能力已实现；未改现有 API/固件，未烧录或部署。

## 8. 研究依据与适用范围

- [Bluetooth Core：架构与隐私地址](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-62/out/en/architecture,-change-history,-and-conventions/architecture.html)：
  私有地址可轮换；观察到的地址不等于永久设备/人的身份。
- [Leith 与 Farrell，RSSI 实测研究，2020](https://arxiv.org/abs/2006.06822)：
  朝向、身体与环境影响信号，RSSI 与距离未必单调；不据此承诺电梯厅精度。
- [Miyagawa 与 Ogawa，协作式 BLE 排队估计，2016](https://www.jstage.jst.go.jp/article/jsp/20/6/20_267/_article)：
  研究双接收器与参与手机的停留信息；其协作实验不能视作被动观测随机手机的验收。

以上资料是本方案的研究依据，非复用代码或模型；实验效果必须在本项目现场验证。
