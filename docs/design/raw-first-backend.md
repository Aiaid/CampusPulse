# Raw-first 后台与小型 D1 结果提案

日期：2026-10-30。状态：**历史评估；已被用户最终“小统计上行、研究 raw 本地留存”默认策略取代。**
保留容量分析供以后明确授权的研究用途。当前不实施默认云端全量 raw。
用户希望优先评估设备上传有界二进制 raw、后台解析与重算，以及“大 raw、小数据库”。
本提案不改变已经完成的八标识 V3 试验；其 [端侧验收](../notes/waveshare-v3-acceptance-2026-10-30.md)
和 [后台验收](../notes/v3-backend-integration-2026-10-30.md) 是当前有限能力的证据。

## 建议与现有实现的关系

建议把在线采集分为：SDK 报告 → 有界复制队列 → 二进制封段 → 独立上传队列 → 私有 R2
→ 可重跑分析任务 → 每统计窗口一条小结果。状态、丢失计数与少量即时摘要继续独立提供。
“全量”只能指声明采集范围中 SDK 交付的报告，不能承诺完整空口捕获。

现有 [CPRAW 归档](../specs/cpraw-archive-v1.md) 的 `offline_import` 绑定已停止的文件、
64 KiB chunk 和整文件 commit；它不是无 TF 节点的在线 raw 协议。可参考它的格式、
CRC、私有认证、不可变回执及清理原则，但在线授权、封段、重启和补传必须另行定义。
现有 [V3 特征接收](../specs/device-v3-ingest.md) 则是逐标识 JSON 与短租约试验，
不能直接解除字段限制后作为此方案；生产默认开关保持关闭。

## 容量证据与候选分段

以下来自私有 2026-10-29 CPRAW 三段的离线聚合，不是并发 Wi-Fi 实测或更密集场景上限。
602,315 条 SDK 报告的文件合计 48,254,664 字节，跨度约 6,762 秒。

| 量 | 本次样本或合成估算 |
| --- | --- |
| 二进制 raw 平均速率 | 约 7.14 KB/s，25.69 MB/h，616.54 MB/day/node |
| 30 秒完整对齐窗 | 平均 214 KB、P95 292 KB、峰值 360 KB |
| 60 秒完整对齐窗 | 平均 429 KB、P95 558 KB、峰值 655 KB |
| 当前冗长 JSON 特征样例 | 约 1,977–2,190 bytes/标识的完整请求；不是紧凑摘要的理论下限 |
| 拟议 60 秒小结果 | 1,440 条/day；合成 SQLite 表及索引约 1.31 MB/day |

KB/MB 使用十进制；KiB/MiB 使用二进制。小结果估算不包含控制、回执、任务或其他表，
也不是现有 D1 schema 的生产测量。当前逐标识 D1 明细并未实现这个长期目标。

首轮可比较 **64 KiB 与 256 KiB** 的完整帧封段，按字节和最大等待时间共同关闭。
256 KiB 是待验证的应用上限：按样本平均约需 2,352 段/day/node；64 KiB 约 9,408 段。
优先评估一次 PUT 对应一段和一份回执，避免再套 manifest/chunk/file 多层回执放大。
分段与 30/60 秒统计窗口独立；窗口可能跨多段，不能把一个段直接当一个窗口。
段内帧必须完整且不越过大小上限，不截断扩展广播后冒充完整 legacy 报告。

## 必须独立冻结的在线契约

- 授权：注册节点、当前及历史采集 grant、配置版本、dataset、用途、placement 来源、
  接受截止和保留期限。离线导入许可不自动授权在线采集，设备声明不等于现场事实。
- 段身份：node/boot/stream、不可复用 segment UUID/序号、精确字节长度及 SHA-256、
  格式版本、首末报告序号和单调时间、时间锚及误差、采集配置、队列/存储损失。
  缺失 UTC 保留未知，服务端接收时间不能替代观察时间。
- 接收：有界流式读取、独立节点/日/待处理字节配额、私有 R2 条件写，再原子保存 D1
  索引和回执。R2 成功而 D1 失败不返回成功；重试精确字节，身份冲突返回不可重试冲突。
- 回执：只确认原始段的持久托管，包含完整身份、长度、字节 hash、首次接收时间和期限。
  解析/分类是另一个版本化状态；未排队或尚未完成的分析不能被伪装成完成。
- 补传：明确何时允许旧 boot、旧 grant 和到期段上传；需要可验证的冻结/采集边界。
  当前 V3 的 retired-boot 拒绝规则不能被默认为已经支持断电续传或离线 drain。

原始地址、名称、载荷和可关联详细分析保持私有。R2 key 由服务器生成，不向公共接口
返回。完整传输但语义损坏的段如需保留，应进入有配额和期限的隔离状态；不能污染
有效报告统计，也不能仅凭上传 hash 声称原始记录完整或准确。

## R2、D1 与可重跑分析

R2 保存精确 raw 段，以及需要时的版本化详细解析/每地址证据产物。D1 长期以每个统计
窗口的小结果为主：观察区间、来源引用、活动度、候选/unknown/conflict 数量、有限分桶、
质量和 parser/extractor/rules/model 版本。公共结果不带地址、名称、token 或原始载荷。

必要的段索引/回执仍会产生约数千条/day/node，必须单独预算行大小、写次数及保留；
不能只把 payload 移到 R2 就宣称数据库已小。避免逐报告写 D1，短期调试明细也要有期限。
回执/预算 tombstone 的期限必须足以防止清理后重放绕过配额，又不能无界积累。

分析任务以来源 hash、时间范围和规则版本构成幂等身份，记录 pending/running/retry/failed/
complete 状态及有界重试；新规则产生新结果，不改写原始段或原回执。使用持久触发/任务
机制，不能仅依靠 `waitUntil` 或进程内队列。大批回放可先离线验证，再评估 Workers/WASM
的有界线上计算；当前 macOS C++ 动态库不能直接部署到 Workers。

重叠段、迟到段和重复任务不能重复累加窗口。缺段、缺时钟、扫描空窗、解析失败和溢出
分别保存；无数据、零观测与旧结果分开。手机/车辆类别仍需已知样本，数量外推仍需现场
标定；模板相似、OUI 或 RSSI 不能直接建立物理身份或人数。

## 无 TF 节点和生命周期

T-Energy 的 PSRAM 只能作为有界易失缓冲。按本次平均速率，每 1 MiB 约 147 秒、
4 MiB 约 9.8 分钟，未扣封装/其他占用且不构成保证。队列应按高峰和目标断网时长设计，
给 Wi-Fi/BLE/TLS、任务栈和 DMA 留余量。若需要断电保留，另行验证 Flash journal 的
真实分区、写放大和寿命预算；本提案不授权改分区、全盘擦除或清除保护数据。

微雪可使用 TF 持久队列，但 raw 记录、上传与分析仍独立控制。BLE 回调只做有界复制和
非阻塞入队；封段、写盘、联网由各自 worker 负责，所有溢出/断网/掉电丢失必须可见。

raw、详细派生物、小统计、索引和回执分别定义期限及删除引用关系。若无标识符统计要
保留更久，需新 policy 明确允许；不能沿用当前派生期限不长于源的规则后暗中延长。
R2/D1 清理需有积压监控、失败重试和可验证吞吐；在线删除不等于 D1 Time Travel 备份消失。

## 下一步验收

先冻结最小在线段格式/grant/回执和掉电边界，再用合成段验证精确重试、冲突、R2/D1
故障、跨 grant/boot、配额竞争、过期与清理后重放。实板同时测 BLE/Wi-Fi 丢失、字节速率、
内存/连续块、重连和功耗；无 TF、满存储、断网及断电分开验收。后台用相同输入验证
重算幂等、段缺口、版本切换和窗口小结果，最后才决定段大小、统计窗和生产资源预算。
