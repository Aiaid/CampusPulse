数量不等于人数或车辆数，模拟/回放也不能冒充现场观察。Cloudflare 承载
网页、API 和数据库；本次工作只涉及 AI Passport 固件及说明文档。

## 2. 构建、镜像与烧录安全

工具链为现有 ESP-IDF 5.5.3，目标 ESP32-C3、8 MB Flash。VS Code 与该命令行
构建使用同一套 ESP-IDF，因此无需重复打开 GUI 构建。

| `build/bootloader/bootloader.bin` | 21,024 字节，保留为独立产物，本次未烧录 |
| `build/partition_table/partition-table.bin` | 3,072 字节，保留为独立产物，本次未烧录 |

| 匹配 ELF SHA-256 | `fedccc087ba8cb290ce80bef367b862ae0c7da64b2a4019807de537bf1aeb4fd` |

完整镜像只用于本地一致性校验，位于
`build/firmware/688e119a04d3b583644a013d4b946b64aaa34f678e72c7c3028661b84e68c42a/`；
**没有烧录该合并镜像**。

只读读取设备分区表后确认实际布局与原工程相同：factory 从 `0x10000`
开始，`ble_raw` 从 `0x400000` 开始。设备实际 factory 为 4032 KiB，与
CampusPulse 建议的 3 MiB/`cardid` 分区表不同。本次没有改变设备布局；
仅写应用区，实际写入终点 `0x14efff` 远低于 `0x356000`，没有覆盖该
保护位置，也没有执行整片擦除。后续如需统一 CampusPulse 分区，必须另行
设计兼容布局并验证 `ble_raw`，不能直接套用当前合并镜像。

COM5 被识别为 Espressif USB-Serial/JTAG（VID:PID `303a:1001`），芯片为
ESP32-C3 revision 1.1、8 MB Flash。COM3/COM4 是蓝牙串口，不是本次目标。

观察到的网络异常包括连接对端重置、一次写数据超时，以及一次证书签名
验证失败导致的 TLS 连接失败。后续重试成功回收数据，说明本次观察中的
退避/重试和扫描恢复有效；不证明这些网络问题已经根治。日志另有 4 次
Wi-Fi reason 8 断开记录，本次没有据此判定为异常丢失。

Device tests 的 PASS 仅限上述串口可观察项目。没有人员操作三键或检查屏幕，
也没有验证音频、实测睡眠电流、电池精度、BLE 分类准确性、丢包真值、云端
逐批内容/序列号或生产凭据边界。不能把 5 分钟结果写成长期稳定或全校覆盖。
