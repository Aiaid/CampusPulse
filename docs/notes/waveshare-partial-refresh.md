# 微雪局部刷新首轮验收

2026-10-29，0.1.4-raw-partial 已刷入同一块微雪板，保留 TF raw 录制和原有数据。
只更新应用区；此前停止会话41,179条接收/写入/同步一致，队列丢包计数0。

## 实现

- 正常目标间隔从30秒改为2秒，按循环开始时间计时，不在刷完后再额外等2秒。
- LVGL继续完整软件渲染为200×200黑白帧；比较上一成功帧计算dirty矩形，
  X按字节对齐，只传该窗口的新RAM字节，使用官方partial波形。
- 第一帧、换页、关键错误/关机、基线失效、累计20次局刷、距全刷60秒或变化
  包围区域超过90%时改全刷；无像素变化则不刷新，周期清屏等待下一次实际变化。
- 正常更新保留GPIO6逻辑供电，避免丢失差分基线。CF/F7序列自身关闭analog/OSC。
  真正关机才显式off并切屏幕供电；硬件错误使基线失效，下一次完整重建。
- 局刷仅写0x24新图，使用0x37 RAM ping-pong；不能把新图同时提前覆盖旧/新两RAM。
  全刷向0x24/0x26写相同完整图像并重载OTP全刷模式。成功后才推进软件基线。

波形、窗口与许可依据为
[Waveshare固定版1.54 V2矩形局刷](https://github.com/waveshareteam/e-Paper/blob/d28b3c4cfc78eef1c6cd6e6e3013654e449d2864/Arduino/epd1in54_V2/epd1in54_V2.cpp)。
159字节partial LUT与板V2官方示例逐字节一致；许可保留于
`firmware/waveshare-raw/licenses/Waveshare-ePaper-MIT.txt`。20次/60秒与90%门限
是本项目初始策略，不是厂商对全部环境的保证。

## 实测

| 约110秒观察窗口内 | 结果 |

| 局刷调用 | 49次 |
| 局刷耗时 | 704–720 ms，中位711 ms |
| 全刷调用 | 9次，含清屏/换页 |
| 全刷耗时 | 1909–1910 ms |
| 页面刷新 | 1–4均观察成功 |
| 结束时接收/写入/同步 | 均9,644条 |
| 报告的队列丢包/无效报告 | 均0 |
| SDK启动、存储、刷新、panic/assert异常 | 本次未捕获到 |

日志观察到连续20次局刷后的全刷清屏。停止/同步/卸载完成后重启，交付状态为
首页RECORDING，持续写卡。用户在聊天中确认“数字与换页显示正常”。

29项主机测试、命令流测试、全/局刷/off轨迹与各command/data/wait故障注入通过；
23个同源LVGL页面/异常状态渲染仍通过边界与重叠检查。
这些不是饱和无线/长期残影、温度范围、局刷功耗或任意电源故障保证。
矩形RAM传输与差分波形不等于已验证窗口外所有栅极的电气隔离。

`.Trashes`/`.Spotlight-V100`，未把无法遍历误报成空目录，也未删除其内容。
