# Cloudflare long-connection transport probe

This independent Worker compares synthetic HTTPS POST and standard WSS transport
against the same byte/hash receipt. It has no storage, production ingestion,
device credentials, MQTT broker, Durable Object, queue, or database bindings.
An ACK means only that this Worker received and hashed the complete message.
It never means durable ingestion and must never release production queued data.

The source/configuration and local tests do not establish deployed-cloud or
hardware performance. Record actual deployment, network path, board, firmware,
TLS validation, and measurements separately. In particular, a Mac proxy path is
not evidence of a direct device path.

## Exact protocol: `cp-link-probe/1`

Both endpoints require `Authorization: Bearer <PROBE_TOKEN>`. Configure a random
token of at least 32 bytes (hex encoding is convenient), at most 256 characters.
The Worker fails closed when the secret is missing, empty, too long, or the
header is invalid. It compares SHA-256 token digests using the Workers timing-safe
comparison. Do not send credentials in URLs; all query strings are rejected.
There is no browser CORS or cookie authentication. Browser-native WebSocket
constructors cannot set the required header; use a device or diagnostic client
that supports Authorization in the upgrade request.

`POST /benchmark` requires exactly `Content-Type: application/octet-stream` and
no Content-Encoding. The body is exactly **1024 or 8192 total bytes**, including
the 20-byte envelope below. The same byte string is one binary WebSocket message
on `GET /ws` (HTTP Upgrade to websocket; public URL uses `wss://`). Fragmentation
at the WebSocket frame layer does not change message length.

| Byte offsets | Meaning |
| --- | --- |
| 0–15 | 16 raw run-ID bytes |
| 16–19 | unsigned sequence number, big-endian, 0–4294967295 |
| 20–end | arbitrary synthetic payload; 1004 or 8172 bytes |

Each successful HTTP request returns status 200 and one JSON object. Each valid
binary WS message returns one text JSON object with exactly these eight fields:

```json
{"protocol":"cp-link-probe/1","kind":"transport_received","run_id":"00112233445566778899aabbccddeeff","seq":0,"bytes":1024,"sha256":"<64 lowercase hex characters>","connection_id":"<lowercase UUIDv4>","colo":"<Cloudflare colo>"}
```

`sha256` covers every byte, including the envelope; `bytes` is the total length.
`run_id` is the lowercase hex of the first 16 bytes. `connection_id` is new for
each HTTP request and stable for each accepted WS session. A fresh HTTP ID does
not indicate whether TLS/TCP was reused: use client connection events for that.
`colo` comes from `request.cf.colo` (fallback `LOCAL` when absent locally).
HTTP responses use identity encoding, fixed Content-Length, and no-cache/no-store
headers. There is no server log of headers, token, payload, run ID, or URL.
Workers observability and preview URLs are disabled for this diagnostic.

The client must await and verify each receipt before sending another message.
The Worker keeps one request in flight per WS session and closes on overlapping
handlers; it has no application queue. Very fast sequential event delivery does
not prove that a remote client waited for a receipt. Run IDs and sequences are
echoed, not stored, deduplicated, or globally ordered across sessions.

The only accepted inbound text message is `close-for-test`, sent after the last
receipt. It returns `{"protocol":"cp-link-probe/1","kind":"closing",
"connection_id":"<same UUID>"}` then close code 1000. Reconnect and verify a
different connection ID. This control response is not a payload receipt.

## Diagnostic bounds and failure behavior

- HTTP bodies are streamed into at most 8192 application bytes and must finish
  within 10 seconds. Oversize bodies return 413; unsupported sizes return 400;
  wrong content type/encoding returns 415; a body deadline returns 408. A false
  Content-Length does not bypass the actual streamed byte limit.
- A WS session accepts at most 256 binary messages and lasts at most 15 minutes.
  The 256th receipt is sent before normal closure (1000). The lifetime timer also
  closes normally. There is no keepalive traffic generated by the Worker; idle
  survival tests should remain within that 15-minute test budget.
- Other text closes 1003, invalid binary size closes 1008, binary messages over
  8192 close 1009, overlapping handlers close 1008, and internal failures close
  1011. After closure an unfinished digest does not send a late ACK. Failures use
  fixed error strings without exception/credential details.
- The 8192-byte limit is an application acceptance limit. Workers receives a
  complete WS message before the JS handler checks its length; it does not give
  this code an 8192-byte preallocation limit on runtime frame buffering. The
  endpoint is secret-gated and for bounded synthetic diagnostics, with no global
  per-account rate limiter. Stop/delete it after testing.
- Cloudflare maintenance, network interruption, client loss, and platform limits
  may close a connection earlier. Ordinary Workers `WebSocketPair` is sufficient
  for this per-connection probe; it does not provide cross-connection coordination
  or durable session state. Production multi-client coordination and persisted
  receipt processing require a separate design.

## Local verification and operator commands

Run commands from the repository root using its existing Node dependencies:

```sh
node --test relay/cf-longlink/worker.test.mjs
WRANGLER_LOG_PATH=/tmp/cp-link-wrangler.log WRANGLER_SEND_METRICS=false \
  npx wrangler types relay/cf-longlink/worker-configuration.d.ts \
  --config relay/cf-longlink/wrangler.jsonc --include-runtime=false
WRANGLER_LOG_PATH=/tmp/cp-link-wrangler.log WRANGLER_SEND_METRICS=false \
  npx wrangler deploy --config relay/cf-longlink/wrangler.jsonc \
  --dry-run --outdir /tmp/cp-link-dry-run
```

The tests execute real local workerd through Miniflare: missing/wrong auth,
exact receipt fields/hash/unsigned sequence, fixed HTTP length, invalid/oversize
and streamed bodies, routes/queries/content handling, 60 sequential mixed-size
WS messages, close/reconnect, and 256-message closure. The overlap-guard test
uses a deliberately delayed digest in a controlled unit fixture because tiny
workerd digests may finish before the next wire event. It is explicitly separate
from the real-runtime tests. The suite does not wait out a 15-minute lifetime or
measure cloud/hardware latency.

Tests cap their compatibility date to the installed workerd binary and UTC day,
and print any difference. The installed local binary initially supported
2026-10-19; this is a local test boundary, not validation of later compatibility
changes. The deployment date is deliberately 2026-10-27: when this probe was
prepared, Asia/Shanghai was already October 28 while UTC was still October 27,
and future UTC compatibility dates were rejected locally.

For local interactive development, create an ignored
`relay/cf-longlink/.dev.vars` containing PROBE_TOKEN securely (never commit it),
then run `npx wrangler dev --config relay/cf-longlink/wrangler.jsonc --local`.
Use the runtime-date override `--compatibility-date 2026-10-19` if the installed
workerd cannot support the configured date; update that override when upgrading
the local runtime. No Node compatibility flag is needed by the Worker itself.

The following commands are for the operator's separately authorized deployment;
local tests and this README do not mean they have been run:

```sh
npx wrangler secret put PROBE_TOKEN --config relay/cf-longlink/wrangler.jsonc
npx wrangler deploy --config relay/cf-longlink/wrangler.jsonc
```

Enter the token only through the interactive secret prompt or secure file/stdin
input, never as a command argument or an `echo` command. The separate Worker name
is `campuspulse-link-probe`; `workers_dev` remains enabled and its configured
custom domain is `pulse-linktest.anend.net`. Domain availability must be checked
before deployment. These commands do not modify the production CampusPulse
Worker/configuration. Delete only this test Worker after measurements if desired:
`npx wrangler delete --config relay/cf-longlink/wrangler.jsonc`.
